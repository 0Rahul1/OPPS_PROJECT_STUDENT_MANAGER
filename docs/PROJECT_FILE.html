1. ABSTRACT & PROBLEM STATEMENT

1.1 Executive Abstract

The Student Management System is an enterprise-patterned software solution built in Modern C++ (C++17) to handle academic student profiles, grade analytics, and persistence across both a relational database (MySQL Server) and a document store (MongoDB). Departing from simplistic in-memory or text-file academic projects, this project implements the Abstract Repository Pattern (IStudentRepository), prepared statements with bound parameters, and bulletproof console stream validation. The system models domain entities using Abstraction, Multilevel Inheritance, Encapsulation, and Runtime Polymorphism.

1.2 Problem Statement & Motivation

Conventional college projects frequently store student profiles in raw arrays or text files. This introduces severe limitations:

  • Lack of Persistence: Volatile memory loses all modified data upon application exit.
  • Absence of Constraints: Text files cannot enforce primary keys, unique email constraints, or valid score ranges (0–100).
  • SQL Injection Vulnerabilities: Ad-hoc string concatenations in database queries jeopardize data integrity.
  • Stream Freezes: Inputting character strings into standard numeric console streams (std::cin) corrupts input buffers and induces infinite crash loops.

1.3 Project Objectives

  1. Architectural Separation: Construct a 4-tier layered architecture separating Presentation, Entity Domain, and Data Access.
  2. Production Database Integration: Connect directly to MySQL Server on port 3306 and MongoDB on port 27017.
  3. SQL Injection Immunity: Enforce parameterized prepared statements (? placeholders) for all user-supplied data.
  4. Automated Academic Standing: Automatically calculate letter grades (A, B, C, D, F) and academic standings (Dean's List, Good Standing, Probation) from percentage marks.
  5. Polyglot Flexibility: Dynamically toggle between relational and document databases at runtime via an abstract interface.

3. OBJECT-ORIENTED PROGRAMMING IMPLEMENTATION

3.1 Abstraction

Implemented via the Abstract Base Class `Person` (src/Person.h). It defines common human attributes (m_id, m_name, m_email) and enforces pure virtual function contracts:

virtual void displayDetails() const = 0; virtual std::string getRole() const = 0;

3.2 Encapsulation

Member variables are declared protected or private. Data mutators validate integrity before assigning values, throwing exceptions or returning false on invalid ranges:

  • Student::setAge(int age) enforces \(15 \le \text{age} \le 100\).
  • Student::setMarks(double marks) enforces \(0.00 \le \text{marks} \le 100.00\).
  • Person::setEmail(string email) validates format against standard RFC regex patterns.

3.3 Multilevel Inheritance Hierarchy

[Person] (Abstract Base: ID, Name, Email, Pure Virtuals) ▲ │ (Single Inheritance) [Student] (Derived: Age, Course, Marks, Letter Grade, Automated Evaluation) ▲ │ (Multilevel Inheritance) [UndergraduateStudent] (Specialized: Semester [1-8], Academic Standing, Honors Logic)

3.4 Runtime Polymorphism & Virtual Destructors

Dynamic dispatch is achieved through the C++ vtable (virtual table). When invoking displayDetails() on base pointers std::unique_ptr<Student>, the runtime dispatches the call to the specialized UndergraduateStudent implementation. Base classes declare virtual ~Person() = default; to prevent memory leaks during polymorphic deallocations.

3.5 Dependency Inversion Principle (SOLID)

High-level UI modules (Menu) depend strictly on the abstract interface IStudentRepository, enabling dynamic runtime switching between MySQL and MongoDB backends without altering UI logic.

4. DATABASE DESIGN & SCHEMAS

4.1 Relational Schema (MySQL Database)

The relational backend utilizes the database student_management with the students table managed under the InnoDB engine to ensure full ACID transaction compliance.

Data Dictionary:

Column Name Data Type Constraint Description
student_id INT PRIMARY KEY Unique institutional identifier
name VARCHAR(100) NOT NULL Student full legal name
age INT CHECK (15–100) Student age in completed years
course VARCHAR(100) NOT NULL Enrolled academic program / degree
email VARCHAR(150) UNIQUE, NOT NULL Unique institutional email address
marks DECIMAL(5,2) CHECK (0–100) Aggregate percentage score
semester INT CHECK (1–8) Current active semester
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP Record creation audit timestamp

4.2 Document NoSQL Schema (MongoDB Collection)

In MongoDB, records are persisted in the students collection with strict validation enforced via the $jsonSchema operator:

db.createCollection("students", { validator: { $jsonSchema: { bsonType: "object", required: ["student_id", "name", "email", "age", "course", "marks", "semester"], properties: { student_id: { bsonType: ["int", "long"], description: "Unique integer ID" }, email: { bsonType: "string", pattern: "^.+@.+\\..+$" }, age: { bsonType: "int", minimum: 15, maximum: 100 }, marks: { bsonType: ["double", "int"], minimum: 0.0, maximum: 100.0 }, semester: { bsonType: "int", minimum: 1, maximum: 8 } } } } }); db.students.createIndex({ student_id: 1 }, { unique: true }); db.students.createIndex({ email: 1 }, { unique: true });

5.2 Prepared Statements (SQL Injection Immunity)

The Data Access Layer executes SQL queries exclusively using bound parameter placeholders (?), preventing user inputs from executing as SQL code:

const std::string sql = "INSERT INTO students (student_id, name, age, course, " "email, marks, semester) VALUES (?, ?, ?, ?, ?, ?, ?)"; std::unique_ptr<sql::PreparedStatement> pstmt(m_conn->prepareStatement(sql)); pstmt->setInt(1, student.getId()); pstmt->setString(2, student.getName()); pstmt->setInt(3, student.getAge()); pstmt->setString(4, student.getCourse()); pstmt->setString(5, student.getEmail()); pstmt->setDouble(6, student.getMarks()); pstmt->setInt(7, student.getSemester()); pstmt->executeUpdate();

5.3 Bulletproof Stream Validation

Console input errors are handled using stream state checks and buffer purges to prevent infinite loops:

if (std::cin.fail()) { std::cin.clear(); // Reset stream state error bit std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n'); // Purge buffer std::cout << " [!] Invalid format. Please enter an integer.\n"; }
